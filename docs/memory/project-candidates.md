# 프로젝트 후보안 (2026-07-30 작성, D-8)

## 전략적 전제

1. **예선 제출물은 문서뿐이다.** 8일 안에 완성된 서비스를 만들 필요 없음. 대신 제안서에 **실측 숫자 한 줄**을 넣을 수 있을 만큼의 얇은 프로토타입을 돌려야 한다.
2. **성능평가 10점이 가장 싼 차별점.** 대부분 팀이 "정성 평가 예정"으로 때울 항목. 정답 라벨이 존재하는 문제를 고르면 여기서 만점 + 기술실현성 20점 근거까지 같이 확보된다.
3. **본선 점수의 60%가 "과학적 타당성(30) + 시연 완성도(30)".** 따라서 예선 분야 선택 단계에서 이미 "본선에서 정량적으로 증명 가능한 문제"를 골라야 한다. 증명 불가능한 문제를 고르면 본선 진출해도 상한이 낮다.
4. 82팀 중 제출 20건. 경쟁팀 다수가 아이디어만 낸다.

## ★ 주력 추천: 임상시험 프로토콜 레드팀 에이전트 (분야 3)

가칭 **TrialRedTeam** — 임상시험 프로토콜 초안을 받아 "이 시험은 왜 실패할 것인가"를 능동적으로 공격하고, 실패 원인을 짚어 프로토콜을 수정 제안하고 재평가하는 멀티에이전트.

### 에이전트 구성

- **Protocol Drafter** — 타겟·적응증·Phase를 받아 프로토콜 초안(적격기준, 1차 평가변수, 대조군, 표본수) 생성
- **Precedent Retriever** — ClinicalTrials.gov v2에서 유사 과거 시험 검색 (동일 적응증·Phase·기전)
- **Red Team / Falsifier** — 검색된 실패 사례의 `whyStopped`에 근거해 초안의 취약점 공격. 근거 없는 주장은 스스로 기각
- **Regulatory Checker** — FDA guidance / 식약처 문서 RAG로 준수 여부 대조
- **Reviser** — 지적된 리스크를 반영해 프로토콜 수정, 리스크 재산출 (self-correcting loop)

### 왜 이 안인가

- **정답 라벨이 이미 존재한다.** ClinicalTrials.gov에 Phase 2 TERMINATED 9,794건, `whyStopped` 자유서술 포함. COMPLETED 시험을 매칭해 negative로 쓰면 균형 잡힌 평가셋이 자동 구축된다.
- **평가 지표가 명확하다.** 중단 여부 예측 AUC / 중단 사유 카테고리 분류 정확도 / 레드팀 지적이 실제 `whyStopped`와 일치하는 비율(hit rate). 제안서에 숫자로 박을 수 있다.
- **"오류를 스스로 인지하고 수정" 본선 10점을 아키텍처가 직접 겨냥한다.** 레드팀-수정 루프 자체가 그 요구사항이다.
- **데이터가 전부 텍스트·구조화 필드다.** 화학 도메인 깊이나 GPU가 필요 없어서, 개발 역량이 강하고 wet-lab 도메인이 약한 팀에 유리하다.
- **분야 3은 상대적으로 경쟁이 얕을 가능성이 높다.** ML 배경 참가자는 분야 1·2로 쏠린다.
- **사회적 가치 20점 서술이 쉽다.** 임상 실패가 신약개발 비용의 최대 비중이고, Phase 2 중단 사유 중 "Recruitment difficulties" 같은 설계 결함성 원인은 사전 교정 가능한 종류다.

### 리스크와 대응

- 본선 기준 문구가 "도출된 **가설·분자 구조**가 생물학·화학적으로 타당한가"로 분자/가설 지향이다 → 프로토콜 안에 타겟-적응증 근거를 Open Targets evidence score로 정량 제시하는 파트를 넣어 보완. 분야 1 요소를 얇게 얹는 형태.
- LLM 사전학습 leakage — 유명 시험은 결과를 이미 알고 있을 수 있다. 대응: NCT ID·약물명·스폰서를 마스킹하고 프로토콜 속성만 주는 blind 평가 프로토콜을 명시. 이 leakage 통제를 제안서에 써두면 그 자체로 성능평가 항목 가점 요인.

### 기술 스택

Python + Claude API(에이전트 오케스트레이션) + ClinicalTrials.gov v2 / Open Targets / Europe PMC / openFDA. 프론트는 본선용으로 미루고 예선에는 CLI 로그 + 평가표만.

## 대안 1: 약물 재창출 가설 생성·반증 에이전트 (분야 1)

Hypothesis Generator → Evidence Retriever(Open Targets + Europe PMC + ChEMBL) → **Falsifier(반증 전담)** → Scorer.

- 장점: 분야 1이 대회 취지 문구("타겟 발굴, 약물 재창출")에 가장 정면으로 부합. 본선 "과학적 타당성" 문구와도 잘 맞는다.
- 단점: **평가셋 leakage 통제가 훨씬 어렵다.** temporal holdout(cutoff 이후 새로 등장한 타겟-질환 쌍을 정답으로)을 써도, LLM이 이미 그 지식을 학습했을 가능성을 심사위원이 지적하기 쉽다. 8일 안에 방어 논리까지 세우기 부담.
- 판단: 주력보다 한 단계 아래. 다만 주력안의 보강 요소로 일부 흡수하는 게 좋다.

## 대안 2: 분자 최적화 루프 (분야 2)

RDKit + MMP 기반 수정 제안 → 유효성/합성가능성 검증 → ADMET·docking oracle 스코어 → 반복.

- 장점: **정량 평가가 가장 강력하다.** GuacaMol / TDC oracle 같은 확립된 벤치마크를 그대로 쓸 수 있어 성능평가 10점은 사실상 확보.
- 단점: 화학 도메인 깊이 필요, 계산 자원 필요, 경쟁 과밀 예상. 그리고 근본 질문 — 기존 생성모델 대비 "에이전트"의 부가가치를 증명하기 어렵다. 심사위원이 "이건 그냥 최적화 알고리즘 아닌가"로 읽을 위험.
- 판단: 팀에 계산화학 전공자가 있으면 1순위로 올릴 만하다. 없으면 피할 것.

## 검토했지만 권하지 않는 방향

- **분야 4 전주기 융합(타겟→분자→임상 전체)** — 4주 본선에 3개 다 넣으면 어느 하나도 완성도가 안 나온다. 시연 30점에서 오히려 손해. 융합은 "주력 1개 + 얇은 보강 1개"까지가 상한.
- **일반 문헌 요약 챗봇** — 심사표가 "단순 챗봇을 넘어"라고 명시적으로 배제했다.
